# ChessPush · 1.0.0

Персональная шахматная утилита на **Tauri 2, React, TypeScript и Rust**.
Рабочие разделы — Главная (часы и рейтинги), Статистика (дебюты и граф партий), Разбор партий, Репертуар из PGN-фрагментов, Знания и Парсер ZST. Qt/Python исключён из текущей
версии; прежняя реализация сохранена в Git под tag `v0.1.0-alpha.1`.

## Подготовка и запуск

Текущий релиз распространяется на условиях [GNU AGPL-3.0-or-later](LICENSE).
Лицензии сторонних компонентов и ассетов сохранены отдельно в [THIRD_PARTY.md](THIRD_PARTY.md).
Исходники версии 1.0.0: [тег v1.0.0](https://github.com/rainfault/chesspush/tree/v1.0.0).

Windows 10/11, Node.js 24+, Rust stable MSVC, Visual Studio Build Tools с Desktop
development with C++ и Windows SDK, WebView2 Runtime.
[Официальные prerequisites Tauri](https://v2.tauri.app/start/prerequisites/).
Все команды выполняются из корня репозитория.

```powershell
npm ci
npm run tauri dev
```

`npm run dev` запускает frontend в браузере: доска доступна, файловые операции
требуют Tauri. Vite используется при разработке; production HTTP-сервера нет.

```powershell
npm run tauri build
```

Исполняемый файл: `src-tauri/target/release/chesspush.exe`.
Установщик: `src-tauri/target/release/bundle/nsis/`.
Быстрая локальная сборка: `npm run tauri build -- --debug --no-bundle`.
Ярлык рабочего стола для установленной версии обновляется скриптом `tools/create_shortcut.ps1`.
После каждого обновления проекта нужно собрать release, обновить установленный
exe и ярлык рабочего стола; одной debug-сборки недостаточно. Используются прежний
каталог установки и identifier, пользовательские данные сохраняются.

## Lichess и главная страница

Главная открывается при запуске: часы и рейтинги Rapid/Blitz с прежней шкалой до 2000. Даты партий не используют стиль часов.

Нажмите «Войти через Lichess» на главной или в настройках. Откроется системный браузер
с OAuth PKCE S256; дополнительные права аккаунта не запрашиваются. Для возврата
приложение временно слушает случайный порт только на 127.0.0.1, максимум 3 минуты.
Вход можно отменить. Обычный HTTP backend не создаётся.

Другой способ: в «Настройки → Аккаунт → Подключить вручную по токену» вставьте персональный токен в поле «Токен» и нажмите «Подключить».
Ник берётся из проверенного аккаунта. Поле очищается после отправки; сохранённый
токен находится в Windows Credential Manager, вне репозитория и SQLite.
«Отключить аккаунт» удаляет локальный доступ, но не отзывает токен на Lichess.
Интеграция хранилища учётных данных сейчас поддерживает Windows.

## Парсер

Откройте «Парсер ZST», выберите `.pgn.zst`, `.zst` или `.pgn`, задайте фильтры и нажмите
«Получить партии». Дебют выбирается поиском или ходами на доске. Ходы до текущей
позиции становятся префиксом поиска; ECO применяется, если префикса нет.
Произвольный FEN меняет доску, но не включает поиск позиции по корпусу.

«Дополнительно»: отдельные рейтинги сторон, минимальная длина, пропуск партий,
ECO, игрок для определения стороны, Bullet и просрочка времени.
«Остановить» сохраняет завершённую часть выборки. Счётчики абсолютные;
полоса прогресса неопределённая, без вымышленного процента распаковки.

В «Сохранённых файлах» хранится история источников и результатов. Нажатие на имя показывает
файл в Проводнике; кнопка справа выбирает источник. «Импорт PGN» сохраняет игры
без фильтров. Импорт нормализуется в отдельный PGN; исходник не изменяется.

## Статистика и репертуар

В «Статистика → Дебюты» одновременно показаны две независимо сортируемые таблицы —
за белых и чёрных. Справа доска: наведение или фокус строки показывает типовую позицию. Поиск по названию/ECO и независимые страницы таблиц сохраняют оба цвета, итоги и доску в пределах окна; число видимых строк подстраивается под высоту.
Колонка «Репертуар, %» отражает долю собственных сыгранных ходов, имеющихся в активном
репертуаре нужной стороны, до выбранной глубины. Определение и источники —
[OPENING_COVERAGE.md](OPENING_COVERAGE.md).

«Настройки → Статистика» задаёт глубину покрытия (1–40 полных ходов, по умолчанию 15)
и позволяет начать статистику заново с текущего момента после подтверждения.
Подключение, первичные партии, PGN, движковые оценки и репертуар при сбросе сохраняются.

«Граф партий» — доска слева и ветка с продолжениями справа, история выбранных ходов,
число партий, частоты и результаты. Щелчок дебюта открывает граф именно его выборки.
Активные прикреплённые PGN отмечают подготовленные ходы, не добавляя сыгранных партий.

В «Репертуар» прикрепляйте PGN-фрагменты за нужную сторону. Плитки показывают
автоматические ECO и названия. Общий репертуар соединяет варианты и совпадающие
FEN-позиции через общую модель KnowledgeDocument/VariationTree. Правки открывают
исходный фрагмент; доступен экспорт общего PGN. Отсоединение обратимо, удаление
документа и его версий требует подтверждения и сохраняет внешний PGN-файл на диске.
Изменения внешних файлов после прикрепления автоматически не отслеживаются.

Один PGN может содержать несколько глав, в том числе экспорт целого исследования
Lichess. Их порядок, названия, стартовые FEN, комментарии и варианты сохраняются.
В общем просмотре и тренажёре поле «Глава» выбирает исходную главу; «Весь репертуар»
оставляет объединённое дерево. В выбранной главе тренируются только её продолжения.
Идентичные позиции с одинаковым набором ответов используют общую историю SRS;
разные подготовленные наборы ответов считаются разными решениями.

«Тренировать» открывает два режима для общего репертуара выбранной стороны.
«Освоение и повторение» использует [FSRS](https://github.com/open-spaced-repetition/fsrs-rs/tree/v6.6.2)
с целевым удержанием 90%. Сессия содержит до десяти позиций: сначала подошедшие
к повторению, затем до пяти новых. Число новых позиций можно выбрать: 0, 5 или 10.
Новое продолжение сначала показывается с комментариями PGN, затем проверяется
без подсказки. Ошибки и подсказки получают Again, самостоятельный верный ответ — Good.
«Полный дрилл» проверяет каждую уникальную позицию, сохраняет покрытие и ошибки
текущего прохождения и не меняет расписание SRS. Прерванное прохождение можно продолжить.

Транспозиции разделяют одну задачу с несколькими допустимыми подготовленными
ходами. Ответы соперника разыгрываются автоматически; при переходе к другой
ветке доска кратко восстанавливает контекст. После ошибки или подсказки нужно
исправить ход на доске, а позже воспроизвести его без подсказки. Исправление и
дополнительная перепроверка ошибки не изменяют первоначальную оценку SRS.
Комментарии PGN доступны при знакомстве, после ответа или подсказки. Выбрать часть репертуара
можно в тренажёре или открыть нужную позицию в общем репертуаре и нажать
«Тренировать ветку». При правках PGN в ChessPush задачи пересчитываются;
история позиции с неизменным набором подготовленных ходов сохраняется.
При изменении набора ответов задача получает собственную новую историю.
Прежние сроки SM-2 сохраняются; состояние памяти переводится в FSRS при следующем
настоящем повторении. Алгоритм и исследовательские основания описаны в
[REPERTOIRE_TRAINING_STRATEGY.md](REPERTOIRE_TRAINING_STRATEGY.md).

Проверка обоих режимов на изолированной SQLite и настоящем Chessground:
`npm run test:repertoire-training`. Проверяются развилки, транспозиции,
альтернативные ответы, подсказки, исправление ошибок и восстановление сессии.
Проверка многоглавного PGN: после сборки задать
`$env:CHESSPUSH_TRAINING_TEST_SCRIPT='tests/repertoire-multichapter-ui.mjs'` и
выполнить `node tools/check-repertoire-training.mjs`. Она использует пять глав
с общей стартовой позицией и отдельную главу с произвольным FEN.

Используется подключённый Lichess-аккаунт. Наблюдение начинается с T0; обязательного
исторического импорта нет. Синхронизация работает при запуске и примерно раз в минуту,
пока ChessPush открыт. Диапазоны и ожидающие партии сохраняются между запусками.
PGN/JSON остаются локально. Пограничные партии с неподтверждённым завершением после T0
не включаются в основную выборку. lastMoveAt не считается точным временем завершения;
абсолютная полнота на границе и при произвольной задержке публикации не обещается.

Stockfish устанавливается отдельно и выбирается в «Настройки → Движок». Очередь,
прогресс и результаты сохраняются; текущие онлайн-партии движку не передаются.
Ранее реализованные аналитические расчёты сохранены в backend, основной интерфейс
Statistics ограничен дебютами и графом.

## Разбор партий и знания

«Разбор партий» показывает собственные синхронизированные партии. Доступны поиск,
фильтры по аккаунту, датам, цвету, контролю времени, тегам и отметке разбора.
Редактор использует общие главы и дерево вариантов: комментарии, NAG, стрелки,
кружки, ветвления и PGN. Сыгранная партия остаётся неизменным источником.
Stockfish включается отдельно для выбранной позиции; ход из его варианта можно
сыграть на доске. Анализ отменяется при переходе к другой позиции.

«Сохранить знание» переносит позицию, выбранный вариант или весь разбор в
библиотеку знаний со ссылкой на точную исходную партию и позицию. Знание можно
подключить к репертуару за выбранную сторону и сразу открыть в тренажёре.
Редактируется тот же документ; обратимое отсоединение сохраняет историю повторений.

## Резервное копирование профиля

«Настройки → Данные» создаёт переносимый файл `.chesspush`: согласованный снимок
SQLite, управляемые PGN из `exports/`, настройки интерфейса и черновики редактора.
Вместе с базой сохраняются знания, разборы, теги, расписание FSRS и учебные сессии.
Внешние корпуса PGN/ZST сохраняются как ссылки, без копирования огромных файлов.
Токены Windows Credential Manager в архив не входят; на другом компьютере нужен
повторный вход в Lichess.

Перед восстановлением показывается состав копии и создаётся страховочный снимок
текущего профиля. Замена выполняется при согласованном перезапуске приложения;
повреждённые архивы не применяются. Обработка прерванного восстановления сохраняет
предыдущий профиль. Движковая очередь после восстановления остаётся на паузе.

Проверки с настоящим приложением в отдельных временных профилях:
`npm run test:game-review`, `npm run test:review-engine`, `npm run test:profile-native`.
`npm run test:profile-ui` проверяет текущий React-интерфейс и восстановление настроек при StrictMode, ошибке чтения и нехватке места в хранилище браузера; используются только синтетические IPC-ответы.
Для движковой проверки требуется отдельно установленный Stockfish.

## Данные

Windows: `%APPDATA%/io.github.rainfault.chesspush.v2/chesspush.sqlite3`.
Identifier сохранён, поэтому уже созданная Tauri-библиотека продолжает использоваться.
Рядом находятся `exports/`. Используется Tauri `app_data_dir`; сырые огромные корпуса
остаются внешними файлами. Схема SQLite версионируется через `PRAGMA user_version`;
SQL migrations находятся в `src-tauri/migrations/`.

Старые локальные `data/` и `outputs/` сохраняются и не публикуются в Git.
Одноразовый перенос старой SQLite-библиотеки выполняется Rust example `migrate_legacy`.
Он читает прежнюю базу, сохраняет игры и историю в Tauri SQLite и создаёт резервную
копию целевой базы перед изменениями. Исходная база, экспорты и файлы настроек остаются
на месте. При первом запуске токен из прежних настроек переносится в Windows Credential
Manager и удаляется из активной SQLite, включая архив настроек. Старые резервные
копии остаются локальными; токен не возвращается frontend и не выводится в лог.

```powershell
cargo run --manifest-path src-tauri/Cargo.toml --no-default-features --example migrate_legacy -- data/chess_training_tool.sqlite3 data/settings.json "$env:APPDATA/io.github.rainfault.chesspush.v2/chesspush.sqlite3" data/migration-backups
```

Последняя команда использует настоящий Tauri/WebView2, синтетические партии,

завершение анализа и повторное использование результатов. `CHESSPUSH_STOCKFISH`
задаёт путь к локальному движку; production SQLite и учётные данные не используются.
При реализации проверены настоящий Stockfish 19 и нативное приложение на
изолированных данных. Подключение к реальному личному аккаунту Lichess в этой
проверке не выполнялось; синхронизация проверяется воспроизводимым локальным HTTP API.
Фактические результаты запусков перечислены в `STATISTICS_IMPLEMENTATION_PROGRESS.md`.
Синтетический performance input создаётся стандартным Node.js ZST stream:

```powershell
node tests/benchmark.mjs
cargo run --manifest-path src-tauri/Cargo.toml --release --no-default-features --example scan -- .qa/benchmark.pgn.zst
```

По умолчанию генерируются 120 000 игр, ожидаются 90 000 совпадений с фильтрами Rust
по умолчанию. `node tests/benchmark.mjs 1000` задаёт другое число повторов fixture.
Измеряется scan/filter; это не benchmark полного экспорта и SQLite-save.

## Приватность Git

Не добавляйте локальные настройки, партии, базы, экспорты и секреты в Git.
`npm run check:privacy` проверяет отслеживаемые файлы, а `node tools/check-privacy.mjs --history`
— все локальные ветки и теги. Проверка сообщает только пути и категории нарушений.
Она не заменяет проверку состава коммита и не может распознать все виды личных данных.

Включите проверку индекса перед коммитом:

```powershell
git config core.hooksPath .githooks
```

История старых веток и alpha-тегов очищена от локальных данных. Для старой копии
репозитория рекомендуется новое клонирование, чтобы случайно не вернуть удалённую историю.
Переписывание Git не удаляет чужие копии и кэш старых коммитов на GitHub;
для серверной очистки может понадобиться обращение в GitHub Support.

```powershell
cargo run --manifest-path src-tauri/Cargo.toml --release --no-default-features --example statistics_benchmark -- $taskBenchmark
node tools/check-statistics-volume.mjs $taskBenchmark
```

Flow проверяет автоматическое обнаружение партии через локальный HTTP API в настоящем native приложении, догрузку за время закрытого приложения и восстановление анализа. Benchmark использует законные синтетические партии, 100/500/1000 повторов и клонированные результаты одного настоящего анализа; это нагрузочные данные, не независимая шахматная выборка. Анализ standard может занять несколько минут. Повторный benchmark переиспользует сохранённый анализ. GUI volume работает только с явно указанным каталогом внутри `.qa`; очередь в нём приостановлена. Личные данные не нужны.

## Граф партий и репертуар

Statistics → Граф партий показывает позиции и реальные ходы подтверждённых личных партий. Доска и граф используют общий проверенный Rust replay; позиционные транспозиции объединены, история конкретного пути и число посещений сохранены отдельно. Фильтры Statistics действуют на фактическую выборку. Репертуарный слой добавляет подготовленные ходы без изменения игровых частот.

Репертуар создаётся и редактируется через общий `KnowledgeDocument`: главы, FEN, PGN RAV, комментарии, NAG и стрелки, устойчивые ID и ревизии. Этот же API предназначен будущему Knowledge. Полная карта реализации, ограничений и измерений: [GRAPH_KNOWLEDGE_IMPLEMENTATION.md](GRAPH_KNOWLEDGE_IMPLEMENTATION.md).

```powershell
npm run test:graph-native
# Отдельная законная синтетическая выборка для GUI-нагрузки:
$env:CHESSPUSH_GRAPH_BENCH_DB = Join-Path (Get-Location) '.qa/graph-volume.sqlite3'
cargo run --manifest-path src-tauri/Cargo.toml --no-default-features --example game_graph_benchmark -- 1000
npm run test:graph-volume
# Сравнение renderer: сначала npm run dev в другом терминале
npm run bench:graph-renderers
```

Тестовые программы используют только отдельные каталоги `.qa`. Они не подключают личный аккаунт и не добавляют демонстрационные партии в рабочую базу. O14/O15 из каталога Statistics пока не подключены к новому документному API; текущее покрытие репертуара доступно в графе.

## Продуктовый интерфейс

Карта по умолчанию исследует выбранный реальный порядок ходов. «Ещё пути» явно включает транспозиции. Подготовленные продолжения репертуара не меняют фактические результаты. Редактор открывается отдельным рабочим пространством; варианты, комментарии, NAG и рисунки сохраняются в общей модели.

## Знания

Каждое знание — PGN-документ общей модели KnowledgeDocument с главами и VariationTree.
Единственная позиция без ходов получает тип «Позиция»; остальные документы —
«Теоретическая заметка». Каталог поддерживает поиск, фильтры по типу и тегу,
создание, импорт файлов PGN, экспорт и удаление с проверкой версии.

Локальный редактор в раскладке Lichess Study сохраняет главы, начальные FEN,
варианты, комментарии, NAG, стрелки и круги, PGN-заголовки и пользовательские теги.
История тегов хранится в SQLite и предлагает ранее использованные значения.
Теги переносятся с экспортом PGN в заголовке ChessPushTags.

Слой «Знания» в графе показывает сохранённые позиции и продолжения даже без
личных партий. Значок книги открывает документ в нужной главе и позиции; из графа
можно создать знание с текущей FEN и ссылкой на источник. Знания не увеличивают
число сыгранных партий и не подменяют статистические результаты.

Нативная проверка на отдельном профиле: `npm run test:knowledge`.
