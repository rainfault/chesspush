# Доска и Home — проверка 28.09.2026

## Что изменено

- `app/rendering.py` снимает внутренний лимит Chromium через
  `--disable-frame-rate-limit`. Qt продолжает синхронизировать представление
  кадров с экраном; системные настройки монитора и драйвера не меняются.
- WebChannel передаёт обновления сразу (`propertyUpdateInterval: -1`), вместо
  стандартного пакета раз в 50 мс. Это задержка подтверждения хода, не частота
  движения мыши: само перетаскивание остаётся внутри Chessground.
- Подтверждение уже нарисованного хода не заменяет FEN повторно. Взятие на
  проходе, превращение и переходы по линии продолжают получать полный FEN.
- Все SVG фигур декодируются до первого взаимодействия. На экранах с DPR < 2
  WebEngine рисует в двойном разрешении, Qt уменьшает результат до размера доски.
  `zoomFactor` компенсирует масштаб для текста и геометрии. При DPR >= 2
  используется собственное разрешение экрана.
- Парсер остаётся созданным и прогретым под непрозрачной главной страницей.
  Переключение больше не инициирует первую видимую загрузку WebEngine.
- В приложении нет постоянного цикла requestAnimationFrame: Chessground рисует
  при взаимодействии и во время анимаций. Отдельный benchmark запускает такой
  цикл лишь на три секунды.

## Измерения

Windows, PySide6 / Qt 6.11.1, экран LG ULTRAGEAR 143.999 Гц, масштаб Windows 125%.
Команда: `python tools/measure_board.py` (для исходного ограничения — `--baseline`).

| Режим | RAF Chromium | Представление Qt |
| --- | ---: | ---: |
| Исходный | 60 кадр/с | 181 swap за тест около 3 с |
| Без лимита, увеличенное разрешение SVG | 481 кадр/с | 143.33 swap/с |

RAF без лимита — внутренние callbacks, **не** число видимых кадров монитора.
Показатель представления вычислен по `QQuickWindow.frameSwapped`. Он отражает
работу теста на данном экране, а не обещает фиксированные 144 кадр/с на любом
оборудовании. Увеличенное разрешение повышает стоимость активной отрисовки;
постоянного рендеринга в состоянии покоя не добавлено.

## Главная страница

`HomeController` асинхронно получает публичный профиль по сохранённому нику.
Токен для этого запроса не требуется и не передаётся. Обновление — раз в минуту
и при возвращении на Home (не чаще раза в 15 с). Таймаут — 8 с; HTTP 429
учитывает Retry-After и паузу минимум 60 с. Смена ника отменяет запрос и
защищена от запоздавшего ответа для предыдущего профиля.

При ошибке запроса рейтинги и шкалы скрыты. Для ещё не сыгранного контроля
фиктивный стартовый рейтинг не показывается. При рейтинге <= 1900 шкалы нет,
1901–1999 соответствует 1–99%, при >= 2000 — 100%. Цвет плавно усиливается.
Иконки Rabbit / Fire взяты из закреплённого официального шрифта Lichess.

Проверены реальные ответы API для сохранённого профиля (оба контроля доступны),
84 unit-теста и отдельный Qt smoke-тест: offline/online Home в обеих темах,
предзагрузка, ходы мышью, стрелки/кружки, клавиатура, превращение, импорт/SQLite.

Источники: [Qt WebChannel](https://doc.qt.io/qt-6/qml-qtwebchannel-webchannel.html#propertyUpdateInterval-prop),
[Chromium frame limiter](https://github.com/chromium/chromium/blob/main/components/viz/common/switches.cc),
[Lichess API](https://lichess.org/api#tag/Users/operation/apiUser).
