# ChessPush — интерфейс до и после продуктовой переработки

Дата набора: **18 октября 2026 года**. Это материалы технической проверки задания `CHESSPUSH_PRODUCT_UX_REDESIGN_TASK.md`.

[Галерея с поиском](index.html) · [Манифест PNG](manifest.json) · [Протокол приёмки](../../PRODUCT_UX_ACCEPTANCE.md) · [Карта переноса интерфейса](../../PRODUCT_UX_MIGRATION_MAP.md) · [Прежняя полная развёртка](../README.md).

В наборе на момент сборки галереи **117 PNG: 6 before и 111 after**. В `native-captures.json` отдельно зарегистрированы **24 снимка финального native Tauri/WebView2**. В `shell-results.json` — **54 записи снимков production frontend через IPC-мост**. Дополнительные снимки тематических сценариев имеют отдельные источники доказательств ниже. Эти количества относятся к разным подмножествам; их нельзя складывать как независимые сценарии приёмки.

Галерея статическая: открыть `index.html` в браузере, найти раздел по имени, теме, размеру или признаку `native`, затем открыть PNG в исходном размере. Числа и время на изображениях — значения тестовых профилей.

## Данные и способы съёмки

**Это не пользовательская статистика.** Основной изолированный профиль содержит четыре легальные тестовые партии и восемь сохранённых запусков Stockfish. Для проверки объёма используется другой профиль: 1000 разных легальных партий, 57 827 позиций, 60 566 посещений и 20 различных первых ходов; готовых движковых оценок в нём нет. Есть подвыборка 100 партий и документ на 400 полуходов. Репертуары создавались и импортировались тестами через настоящее общее документное ядро.

Пользовательская SQLite-база, подключённый личный аккаунт и установленное приложение не служили источником снимков. Изменения тестовых документов, фильтров, репертуарного слоя и синтетических учётных данных выполнялись в изолированных каталогах `.qa` либо в браузерном тестовом контексте. Ввод токенов и реальные секреты в набор не включены.

| Получение | Что означает | Где искать точное описание |
|---|---|---|
| **Native** | Снимок клиентской области работающего Tauri/WebView2 с настоящим Rust/SQLite backend | [native-captures.json](native-captures.json); дополнительные native-проверки графа — [evidence/graph-native.json](evidence/graph-native.json) |
| **Production frontend + IPC bridge** | Собранный frontend открыт в headless Microsoft Edge и вызывает настоящий изолированный native backend. Это действующие компоненты и нативные данные, но снимок не является кадром окна Tauri | [shell-results.json](shell-results.json), [scenario-results.json](scenario-results.json), [evidence/context-ui.json](evidence/context-ui.json) |
| **Управляемая IPC-граница** | На границе ответа/события заданы отсутствие аккаунта, пустая история, отсутствие анализа, offline, 429, истёкший доступ либо refresh. Проверяется реакция настоящего UI | [evidence/states-ui.json](evidence/states-ui.json), [evidence/volume/interactions.json](evidence/volume/interactions.json) |
| **Focused editor** | Общий React-редактор через Vite и IPC к настоящему backend. Ошибка записи управляемая; конфликт ревизии и удаление узла реальные | [evidence/repertoire-ui.json](evidence/repertoire-ui.json) |

Управляемое изображение offline/429 не доказывает фактическое отключение сети или ответ внешнего Lichess. Отдельный native flow проверяет настоящий протокол синхронизации с локальным тестовым HTTP-сервером, SQLite и Stockfish. Подмена результата системного файлового диалога в сценарии парсера не подменяет импорт PGN, parser, storage или replay.

Эти 24 статических кадра пересняты с `animations: disabled`: фиксируется конечное состояние CSS-перехода, а не начало fade. ## Темы, размеры и масштаб

Основная матрица: **light/dark × 900×700, 1440×960, 1920×1080 CSS px**. Для bridge-снимков DPR=1. У native-снимков в манифесте записано фактическое численное значение около 1; небольшая погрешность представления не означает отдельный масштаб Windows.

В объёмном профиле дополнительно снята эффективная браузерная конфигурация:

| Эмуляция | CSS viewport | DPR | Граница |
|---|---:|---:|---|
| 125% при исходном рабочем пространстве около 900×700 | 720×560 | 1,25 | Уменьшенный CSS viewport и плотность устройства |
| 150% при том же исходном пространстве | 600×467 | 1,5 | Округление эффективной высоты |

Это **не проверка фактического изменения системного масштаба Windows**. Увеличенный текст, screen reader и полный WCAG-аудит всех состояний отдельно не заявляются пройденными. Выборочный численный контраст токенов находится в [contrast.json](contrast.json).

Размер PNG не всегда равен viewport: before может быть полностраничным кадром; внутренне прокручиваемые области показывают выбранный участок. Для after точные условия следует брать из соответствующего источника metadata, а не выводить DPR по имени файла.

## Ограничения чтения набора

- Статический кадр не доказывает синхронность навигации, идемпотентность сохранения или восстановление после restart. Для этого есть тесты и [протокол приёмки](../../PRODUCT_UX_ACCEPTANCE.md).
- Автоматическая публикация новой партии проверялась реальным flow с локальным HTTP API; сохранение порядка/фокуса отдельно перепроверялось управляемым refresh на настоящем индексе. Это не один атомарный стресс-тест внешнего Lichess под указателем.
- Часть ранних инструментированных замеров объёма собрана до последних защит контекста. Граница версии явно указана в [volume/verification-summary.json](evidence/volume/verification-summary.json). Отдельная [финальная native-серия](evidence/native-performance.md) имеет другой метод и не смешивается с ранними числами. В ней карта не вызывает полный отчёт; явная полная статистика по 1000 партиям всё ещё передаёт около 52,48 МБ и имеет измеренные longtasks. Это сохранённое ограничение, а не утверждение об устранении всех задержек приложения.
- Пять пользовательских заданий подготовлены в протоколе, но человек ещё не проходил исследование понятности. Технический проход агента не заменяет его.
- Прежние `screens/light`, `screens/dark`, исходный `screens/manifest.json` и старая галерея сохранены. Новый каталог не переписывает историю аудита.

## Сборка и проверка

Из корня репозитория:

```powershell
node tools/build-product-ux-gallery.mjs
```

Генератор создаёт `manifest.json` и `index.html` по текущим before/after PNG. После новых финальных прогонов его нужно выполнить повторно. Точное количество файлов на текущий момент находится в манифесте; текстовое количество выше фиксирует дату этой сборки каталога.
