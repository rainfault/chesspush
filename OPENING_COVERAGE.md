# ChessPush — покрытие дебютов репертуаром

Решение от 18 октября 2026. Источники ниже описывают существующие подходы; формула ChessPush — собственное определение для статистики личных партий, а не заявленный отраслевой стандарт.

| Подход | Основание | Решение для ChessPush |
|---|---|---|
| Сравнение названий/ECO | Коды обозначают семейства, а не множество подготовленных ответов. Один ECO объединяет много разных позиций. | Недостаточно для покрытия. ECO используется только для группировки и названия. |
| Позиция + подготовленный ход | ChessTempo хранит позиции независимо от порядка достижения и объединяет одинаковые позицию/ход между репертуарами ([официальное руководство, §17.4.6](https://chesstempo.com/manual/en/manual.html)). | Используем общие PositionKey и UCI; транспозиции и FEN-фрагменты распознаются без сравнения строк PGN. |
| Полностью покрытая линия до глубины D | Бинарная проверка всей истории. | Скрывает частичную подготовку; перестановка ходов обрывает строковое совпадение. Не выбран основным процентом. |
| Вероятностное покрытие будущих ветвей | Chessbook подбирает ветви по встречаемости на уровне игрока и показывает пробелы ([официальное описание](https://chessbook.com/repertoires)). Публичной точной формулы на этой странице нет. | Не выдаём небольшую личную выборку за вероятность всех будущих партий; внешний explorer не требуется. |
| Взвешенное покрытие фактических собственных решений | Часто встречающиеся решения в личной практике дают больший вес. | Выбран воспроизводимый процент совпадения сыгранных продолжений с подготовкой, отдельно по стороне. |

Для группы дебюта O, стороны S и глубины D полных ходов:

- A — все фактически сыгранные собственные решения в партиях группы O/S с номером хода от 1 до D включительно.
- R — множество пар `(PositionKey до хода, UCI)` из активных прикреплённых репертуаров стороны S или обеих сторон, только текущих ревизий.
- `coverage = 100 × count(a ∈ A: pair(a) ∈ R) / |A|`.

Если решений нет, результат отсутствует (`null`, UI «—»). Если решения есть, но репертуара нет, результат 0%. Ходы соперника не входят в знаменатель. Повторное посещение в фактической партии — новое решение; повтор одного и того же подготовленного узла или файла не умножает покрытие. Разные собственные продолжения в одной позиции считаются раздельно: подготовленный Nf3 не делает сыгранный Bc4 покрытым.

Это доля **своих сыгранных ходов, присутствующих в репертуаре**, а не доля всей теории, вероятность победы, знание материала или оценка качества хода. Процент зависит от собственной выборки и длины партий. Неучтённые в истории альтернативы не входят в знаменатель. Более глубокое значение D включает дополнительные реальные решения; коротким партиям не приписываются отсутствующие ходы.

Глубина — настройка в полных ходах (1–40, по умолчанию 15). Номера берутся из фактической партии, а не из условной нумерации прикреплённого FEN-фрагмента. Метрика возвращает числитель, знаменатель, число партий, число активных документов, глубину, источник и версию `observed-own-decisions-v1`. В интерфейсе они доступны в tooltip ячейки. Изменение настроек или источников вызывает пересчёт, не меняя фактические N/В/Н/П.

Группировка использует `(аккаунт, сторона пользователя, ECO, полное название варианта)`. Белые и чёрные — две независимые таблицы; одинаковый дебют имеет отдельную строку в каждой.

Типовая позиция: кратчайшая проверенная каноническая линия точного ECO/названия из уже поставляемого CC0 каталога [lichess-org/chess-openings](https://github.com/lichess-org/chess-openings). Сам каталог публикует PGN типовых продолжений и рекомендует позиционную классификацию с учётом транспозиций. Если канонической линии нет, используется соответствующая классифицированная позиция реальной партии. Неизвестный дебют не получает вымышленную позицию.

Реализация использует существующие knowledge_node_index, game_occurrences и общую шахматную модель. Текущая ревизия индекса проверяется; старый ещё не проиндексированный replay имеет read-only fallback. Один ответ строится в согласованном read snapshot SQLite. Наведение на строку не обращается к API и не запускает движок.
