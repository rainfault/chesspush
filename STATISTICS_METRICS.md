# Каталог показателей статистики ChessPush

86 показателей для проектирования Statistics. Определения выборки, анализа и интерпретации согласованы с [основной спецификацией](STATISTICS_SPEC.md), разделы 4–10. Каталог задаёт вычисления и переходы к шахматному материалу; наличие строки не означает наличие реализации.

## Общие единицы и условия

- `N` — уникальные завершённые личные партии с известным результатом в выбранной группе; `W,D,L` — победы, ничьи, поражения. `s=1/0.5/0` — результат партии. Для рейтингов, часов, дебютных границ и анализа используются собственные пригодные подвыборки; их размер показывается отдельно.
- `n` — пригодные личные решения; `e` — пригодные события или эпизоды. Для процентов явно указано, считается доля партий, решений или событий. Нет доступных случаев — отсутствующее значение, а не 0%. Числитель, знаменатель и число исключений сохраняются.
- `q=(W_sf+0.5D_sf)/1000` — ожидаемое очко модели Stockfish при WDL в промилле. `q*` и `q_a` — результат лучшего и сыгранного хода из одного корня с одинаковой историей, POV автора хода и профилем. `Lq=100×max(0,q*−q_a)` измеряется в процентных пунктах ожидаемого очка. Это не личная вероятность победы.
- `pL` — преобразование cp по методике Lichess; `LL` — собственная same-root потеря этого представления в процентных пунктах. `LL_upstream=max(0,pL_before−pL_after)` берётся из последовательных upstream before/after evaluations с POV автора хода, upstream alignment, начальной оценкой и mate-политикой. Только LL_upstream используется для численной совместимости Accuracy; LL из root-pairs не подменяет её. `cp`, `mate`, terminal outcome и tablebase result сохраняются разными типами. `ACPL`, `Lq`, `LL` и Accuracy не взаимозаменяемы; точные определения и upstream-ссылки — [§6](STATISTICS_SPEC.md).
- `opportunity_v1`: из POV пользователя `G=q1−q0≥0.10` после хода соперника; сильный ответ имеет `R=max(0,q1−q2)≤0.02`. `advantage_v1`: два последовательных пригодных личных решения при `q≥0.90`, выход при `q<0.80`. `defense_v1`: трудное состояние `q≤0.10`, выход `q>0.20`. События подтверждаются по правилам [§7](STATISTICS_SPEC.md). Состояния q до и после собственного решения хранятся явно; новый эпизод не склеивается через подтверждённый выход.
- Пороги выше и `Lq≥10 п.п.` — предлагаемые параметры ChessPush, а не шахматные теоремы. Их version ID и параметры входят в результат; sensitivity: `G=0.05/0.10/0.20`, `R=0.01/0.02/0.05`, вход преимущества `0.80/0.90/0.95`, тяжёлая потеря `5/10/20 п.п.`. Дополнительные `ε`, диапазон равенства, размер окна и достаточный остаток часов задаются явно в соответствующем профиле.
- `spent` — восстановленное время, списанное с часов, в секундах; `remaining_before` — остаток до решения. `relative_remaining=remaining_before/effective_initial`. Формула Fischer, исключения первого и последнего ходов, точность clock и нестандартные контроли — [§8](STATISTICS_SPEC.md). Неизвестные участки не распределяются произвольно между ходами.
- `Kpos` — позиционный ключ с variant, размещением, стороной хода, рокировками и только легальным en passant; `Kline` — исходная позиция и последовательность UCI. Для engine cache требуются также rule50 и история; ключ дебюта их не заменяет. Для частоты позиций показываются отдельно уникальные партии и посещения. Политика первого посещения применяется только там, где явно указана. [§5](STATISTICS_SPEC.md).
- Фаза, тип окончания, пешечная структура и версия репертуара — явные классификаторы. Число партий, сегментов и решений различается; одна партия может пройти несколько типов окончания. Фазы определяет закреплённый Divider, а не один фиксированный номер хода. [§9](STATISTICS_SPEC.md).
- A — PGN, metadata, правила и сопоставление с предоставленным справочником/репертуаром без движка; B — engine или tablebase; C — новая семантическая модель и её валидация. A не означает «уже реализовано». Стоимость оценивает получение всех необходимых данных: низкая — replay/SQL, средняя — позиционный индекс/ресэмплинг, высокая — анализ/перепроверка или исследование. Общие движковые данные переиспользуются, новый запуск для каждого графика не нужен.
- P0 — первая рабочая вертикаль без движка, включая базовые часы и replay фаз; P1 — движковый цикл и подробная аналитика времени; P2 — дальнейшие расширения. P0/P1/P2 — приоритеты каталога, а не номера этапов или обещание одного релиза. Первое движковое ядро — loss, Accuracy/ACPL, существенные ошибки, возможности, реализация, защита и состояние выхода; полный набор строк P1 вводится частями. Подробные time bins, типы окончаний, Syzygy и сопоставимые динамические группы относятся к углублению на этапе 3 основной спецификации. Ровно две темы Lichess, плотные таблицы, без мелких объясняющих подписей. Названия ниже — рабочие термины спецификации; длинные определения не переносятся в основной интерфейс.
- Любое значение наследует фильтры account, source, platform/perf/variant, exact control, цвет, период и пригодность данных. Показывать N, покрытие и интервалы; ходовые/событийные интервалы получают ресэмплингом целых партий. Score с ничьими не является биномиальной долей побед. Скользящие окна зависимы. [§4 и §10](STATISTICS_SPEC.md).

## Дебюты позиции продолжения и репертуар

В O01–O15 действуют раздельные режимы position/path и цвет пользователя. Именованный дебют берётся из закреплённого справочника по последней подходящей позиции; aliases не удваивают партии. Неименованные позиции сохраняются. Позиционный граф может иметь циклы. Для сравнения с репертуаром требуется предоставленный пользователем PGN и его версия. [§5](STATISTICS_SPEC.md).

## Правила использования каталога

Каждая строка задаёт независимый вопрос. Разрезы по цвету, контролю, дебюту, фазе и времени переиспользуют одну версию вычисления. Производные таблицы хранят ссылку на исходные события и analysis runs; отсутствие исходных данных блокирует только соответствующий показатель.

Первый переход из любого агрегата открывает его собственный знаменатель и набор партий/решений; следующий — конкретный `(game_id, ply)` с доской, ходом и доступным доказательством. Создание знания или задания из найденного случая — явное действие пользователя. Автоматическая подборка повторяющихся случаев не превращается в автоматический стратегический диагноз.

Гипотезы о слабом дебюте и прогрессе показываются с размером выборки, сопоставимостью и интервалом разницы. Массовый просмотр ветвей допускает описательный рейтинг случаев; утверждения о статистической значимости требуют учёта множественных сравнений. Общий «индекс шахматной силы», психологические ярлыки, сила по одному Accuracy и «освоенная линия» из быстрого хода в каталог не входят.
