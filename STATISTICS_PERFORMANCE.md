# Производительность Statistics

15 октября 2026. Windows x86_64, AMD Ryzen 5 5600H (6 ядер/12 потоков),16,48 GB RAM. Rust release, один повтор после прогрева/сборок; это наблюдения на этой машине, не SLA. Сырые результаты: .qa/statistics-performance-b3eef979/statistics-performance.json.

## Нагрузка и границы

Одна законная партия33 ply, 100/500/1000 повторов; сохранённые оценки одного настоящего Stockfish19 клонируются для нагрузки. Это не независимые игровые наблюдения и не проверка статистической значимости. Полный вычисленный domain report сериализован для сравнения, затем compact ограничивает только evidence. Native сборка и память WebView измеряются отдельно.

## Настоящий движок

Stockfish19, standard без custom overrides: nodes2M/movetime5s на поиск,1thread,Hash128MiB. Полная партия33 ply: 157.08s,34позиционных оценки и33same-root сравнения; handshake/config validation 854.2ms. Первое выполнение измерено отдельно; последующие benchmark переиспользуют именно этот сохранённый run, не выдают cache hit за новый анализ. reported_nodes_in_best_evaluations относится только к best evaluations, не ко всем поискам.

Standard рационален для фоновой очереди; быстрый режим и отмена/пауза доступны. Скорость зависит от позиции/железа/лимитов. Бюджет и профиль всегда видимы и несопоставимые профили не смешиваются.

## Native GUI и API flow — PASS

Native executable собран в **debug**, поэтому его время полного расчёта нельзя выдавать за release GUI. Источник — изолированная SQLite с 1001 синтетической законной партией и 1001 сохранённым run (клонированные оценки одного настоящего анализа); 17 017 личных решений. Worker приостановлен до запуска и остался приостановлен, задачи не выполнялись. Проверены все шесть разделов, оба направления фильтра, light/dark, реальные semantic assertions и скриншоты.

Обнаруженные узкие места и изменения: повторяющийся evidence JSON уменьшен на 86,8%; страницы ограничены 100 и защищены snapshot fingerprint. Опрос очереди каждые 10 с обновляет статус; полный отчёт пересчитывается при событиях/смене фильтров и контрольном минутном обновлении. Это устраняет непрерывный пересчёт, когда debug-запрос дольше 10 с. Одновременные запросы одного view объединяются. Бесконечный фон и OS service не нужны.

Повторный свежий API → SQLite → GUI → настоящий Stockfish → restart flow прошёл на окончательном UI. Автоматическое обнаружение после публикации: 63.16 с при штатном polling 60 с, без кнопки Sync. Это интервал обнаружения в fixture, не обещание задержки публикации Lichess. Quick **custom 100k nodes/200ms**, 1 thread/Hash16MiB, полная партия 4 ply: 6.77 с с validation/очередью. GUI heartbeat p99=20.6 мс, max=71.4 мс. Применение фильтра на трёх партиях: 173.0 мс. Offline catchup и восстановление анализа проверены отдельными перезапусками; личный production account не использовался.

Release CPU-расчёт на 1000 партиях подтверждён, но полный release GUI не измерялся; debug-загрузка и фильтры на таком объёме требуют 12–21 с. Native сценарий проверяет отзывчивость и фактические результаты на этом объёме. Объёмы больше 1001 партии и тысячи различных длинных позиций требуют отдельных измерений. Успешный probe реальных Syzygy-файлов и работа с production аккаунтом в этот benchmark не входят.
