# Покрытие реализации Statistics

Матрица на 15 октября 2026 года сопоставляет все **86** строк `STATISTICS_METRICS.md` с текущими Rust/SQLite/React исходниками. Идентификаторы, названия и категории сверены с извлечённым каталогом `.qa/statistics-catalogue.json`: G16 + O15 + Q11 + E11 + T10 + S14 + P09 = 86. Отсутствие партий, часов или пригодного анализа означает отсутствие значения, а не отсутствие реализации.

Статусы: **COMPLETE** — реализовано и проверено; **PARTIAL** — реализована часть показателя; **MISSING** — реализации нет; **BLOCKED** — требуется внешняя зависимость. Итог по 86 строкам: **76 COMPLETE, 2 PARTIAL, 8 BLOCKED, 0 MISSING**. E05 и S05 частичны только в необязательном табличном фрагменте: mate recheck и engine equal-band аналитика реализованы и проверены. O14/O15 требуют предоставленного версионированного PGN-репертуара; S06 требует реальных локальных Syzygy-файлов и успешных rule-aware probes; P05–P09 относятся к исключённой категории C.

COMPLETE означает подтверждение кода unit/integration проверками и действующих GUI-путей native сценариями. Это не заявление об отдельном E2E assertion каждого численного поля: точные numerical goldens и общие fixtures перечислены в легенде ниже. Отсутствующие входные данные остаются missing, а условные зависимости — явными статусами.

## Границы доказательств

- Loopback API tests проверяют реальную HTTP/NDJSON обработку, 429/partial/offline/restart и generation guards без пользовательских credentials. Они не доказывают SLA публикации партий реальным Lichess. Граница pre-T0 и недостоверное время завершения сохраняют uncertainty.
- PGN/JSON, replay и run/profile/method versions сохраняются; статистика пересчитывается локально. Переключение профиля не смешивает оценки. Same Kpos не подменяет rule/history context для движкового кэша.
- Clock quality, sample и missing reasons видны отдельно. Нулевой rounded spent не объявляется premove; связь времени с потерями не объявляется причиной. Границы фаз и определения сессий являются записанными операционными политиками.
- Положительная проверка synthetic tablebase observation или manifest не равна успешному чтению реальных Syzygy. Ненулевой halfmove/repetition-sensitive контекст, castling и неподходящие таблицы исключаются; `tbhits` не используется как доказательство точного результата.
- Evidence paging не уменьшает числители/знаменатели. Полный список доступен через `statistics_evidence` с `kind/key/offset/limit`, а revision guard требует открыть список заново после изменения набора данных. Маршрут, дальнейшие страницы и stale-snapshot отказ подтверждены native E2E вместе с unit compaction tests.

Реальный production-account прогон, успешное чтение реальных Syzygy и нагрузка 10k партий этими проверками **не подтверждены**.


Финальная дополнительная перепроверка: `node tools/check-statistics-native.mjs` целиком PASS на новой SQLite, все четыре фазы, `.qa/statistics-native-aaVmpE`; `cargo check --release --lib` с desktop default features PASS. Последний GUI volume дополнительно проверяет отображение гистограммы Q02 и отсутствие кнопок страниц вне закрытых таблиц.
